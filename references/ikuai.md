# 爱快：可选的源设备域名补充保护

只在用户要求路由层保护时使用。源 IP 必须由当前租约/MAC/静态绑定验证，不能用旧聊天中的地址。把规则限定到这些设备；保留管理入口、LAN、Tailscale、第三方 API 和代理节点本身。

域名过滤能拦截部分直接 HTTP Host/TLS SNI 请求，看到的代理连接通常是加密节点地址。IPv6、QUIC、ECH、DoH、IP 直连、同机转发和外部网络可能绕过这种识别。它无法识别 OAuth 登录态。禁止将它作为唯一 kill switch，禁止屏蔽整个共享 CDN 或把全部外国 IP 黑掉。

## V4 适配参考

这个方案来自 V4 `url_black` 机制；其他版本先从实际后台网络请求确认 schema，不假定 V3/V4 相同。不抓取 WAN 账号、全量系统私密报告或不相关终端清单。凭据仅从用户授权的安全来源读取到内存，不写入代码/命令行/发布包；保持 TLS 校验，不把控制台转发到公网。

同源后台 API 通常是 POST `/Action/call`。只读请求示例：

```json
{"func_name":"url_black","action":"show","param":{"TYPE":"total,data"}}
```

已观察的 V4 响应：`code:0`，数据在 `results.data`，与部分旧版格式不同。生成器的 `ikuai-v4-plan.json` 是待审阅 `add` 请求，**不会发送**。`mode:0` 为黑名单，域名同时列自身与 `*.` 子域，单个明确源 IP，全天周计划。

## 有限范围应用

1. 从已登录的可信会话只读获取现有 URL 规则，保存私有备份。记录原规则 ID、顺序、启用状态、源设备范围。核对旁路 IPv6 和 URL 白名单设置，只读即可。
2. 检查 `ClaudeGuard` 名称是否已存在；存在则停止新增，核对归属，不覆盖。不同的独立部署应选新的、不超过 15 个 ASCII 字符的名称。
3. 向用户说明原生 Anthropic API 也会被这组域名规则阻断；只有独立第三方域名才可能不受影响。应用前检查是否存在授权的原生 API 直连需求。
4. 用户授权后仅新增这一条规则；读回 ID、源 IP、域名、启用和时间字段，保存 receipt。只检查已有 ACL/WAN/DNS/DHCP 是否未变化，不修改它们。
5. 做用户授权的实际验证；范围内目标直连失败、指定代理通、国内对照通。对有权测试的端点操作，不能把“拨号在线”当端到端验证，也不能主动重拨宽带来测试隔离。

回滚：按 receipt 查回该 ID，确认名称/源/域名仍与本次新增一致，再删除或在后台禁用。已观察的 V4 删除结构是 `action:del,param:{id:"<recorded-id>"}`；版本未核实不得直接发送。不按名称批量删，不恢复全路由配置来撤销一条 URL 规则。

来源：[爱快官方支持入口](https://www.ikuai8.com/support.html)。本 Skill 不依赖公开稳定 API 承诺；实际固件/请求为适配依据。路由配置生成器仅做离线结构测试。
