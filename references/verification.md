# 验证、故障测试与状态报告

## 验收对象

逐个列出：Chrome 官方网站、Claude Desktop、Claude Code 独立二进制、OAuth 外部浏览器、子进程/MCP/Cowork。没有安装或无法访问的对象标待验证。不要把一项成功推给其他对象。

先记录固定出口和所有中转：客户端 → 本地监听进程 → 唯一节点 →（如有）中转的下一跳 → 服务。域名规则命中代理组不代表该组固定，也不代表中转服务器不转发到其他出口。SSH 检查仅针对用户授权的服务；不公开完整配置和密钥。

## 最小测试矩阵

| 状态 | 保护对象期望 | 无关对象期望 | 必要证据 |
|---|---|---|---|
| 正常 | 使用指定代理/节点 | 国内站、私有 API、LAN 按既定规则工作 | 有效策略、进程连接/规则命中、出口观察 |
| 节点失效，代理仍运行 | 新连接失败，不转直连或其他节点 | 在授权测试范围内不受改动影响 | 本地监听仍在，目标节点不可用，客户端失败及无备用路由证据 |
| 代理软件退出 | 新连接失败 | 不依赖它的对象仍可用 | 监听和残留核心都已退出，目标外部连接被拒绝/未成立 |
| IPv6 / WebRTC / UDP / DNS | 按声明的范围阻断或走指定路径 | 不把“没有候选”称为代理 UDP 成功 | 分协议证据；不支持的标明缺口 |
| 恢复 | 原固定出口恢复 | 无关配置未改 | 原配置哈希/差异、有效规则、正常请求 |

测试前取得中断授权，保存配置，确认没有下载/会话/远程连接依赖该代理。用专用可恢复的测试路径，不删除节点、不更改账号、不重启路由器、不伪造登录或提交消息。可访问端点必须由使用者有权测试；不向随机服务器发送伪装 Host/SNI。

正常无凭据探测使用公开静态页面或自有探测端点；实际登录由使用者确认。`curl` 的出口只代表该 curl 请求；需要把同一时段真实目标进程连接与 core 日志关联起来。不得使用抓取 cookie、登录令牌或聊天正文来做验收。

节点故障测试应保留本地监听、只让目标出口不可达，确认没有自动换组/直连。代理退出测试要检查服务模式、守护进程、残留核心和自动重启；仅关 GUI 不一定退出。每次只改变一个条件，恢复后再做下一项。用 finally 恢复并独立核对；恢复失败就停止其他写操作并告知用户。

对 TCP-only 的观察不能写“全部 UDP/IPv6 无泄漏”。测试时看到失败且没发现外部连接是限定窗口的证据；不要称数学意义上的绝对保证。DNS 是独立路径，浏览器预解析、系统解析和插件请求可能不走 PAC。认证域名清单可能变化，不能覆盖所有未来域名。

## 判定和报告

报告列出每对象的配置来源、改动范围、恢复路径与证据时间。五种状态必须区分：生成、应用、有效策略、实际正常路径、故障测试通过。没有完成的测试保留 pending，不能因脚本返回 0 或 HTTP 200 改成通过。

最小阻断条件：目标出现直连、备用节点、无效强制策略或保护程序规则缺失时，先停止该目标的官方登录/请求，保留管理通道并修复。不得悄悄用直连兜底来让测试变绿。
